# Project notes (persistent memory)

## What this repo is
Full-SSR video archive viewer: FastAPI + Jinja2 + boto3 browse tree over an
S3-compatible bucket, plus a Vanilla-JS accessible modal video player.

## Archive layout
- Key layout: `<common_prefix>/<camera>/<YYYY>/<MM>/<DD>/<HH>/<MM>-<SS>.mp4`,
  i.e. the filename is **minute-second**, the hour comes from the folder name.
  Truncated recordings end in `-truncated.mp4`.
- An hour holds 0 to 60 clips; whole hours, days and months can be empty.
- S3-compatible backends to expect: Garage, MinIO, Ceph, AWS.
  - Garage and MinIO need `signature_version="s3v4"` for presigning; botocore's
    default for S3 is SigV2, which Garage rejects with `403 Forbidden: Garage
    does not support anonymous access yet`. `PRESIGN_SIGNATURE_VERSION` in
    `app/s3.py` pins s3v4 for every browser-facing URL.
  - Range requests (`bytes=0-1023`) return 206 + `Content-Range`.
- All configuration is environment-only (see `env.example`); nothing about a
  deployment belongs in this file.
- Variable names follow the AWS SDK conventions so one `.env` can also serve the
  archiver that writes the keys: `S3_BUCKET`, `S3_PREFIX`, `AWS_ENDPOINT_URL_S3`,
  `AWS_REGION`, optional `S3_KEY_TIMEZONE`. Credentials and the endpoint are not
  modelled in `Settings` at all - the default botocore chain owns them, so
  `AWS_PROFILE` and instance roles work. Only `ARCHIVE_HOST_MAP` and the
  `ARCHIVE_*` tuning knobs keep the project prefix, and addressing style is
  configurable per mapped host only.
- The signing region is required (`AWS_REGION`, or `AWS_DEFAULT_REGION`). A
  presigned URL cannot be re-signed after the browser receives it, so a wrong
  region fails in the browser as `400 AuthorizationHeaderMalformed` instead of
  at start-up. Garage does name the expected region in that response body, but
  only a person reading it benefits, so no default is guessed.

## Why `tests/conftest.py` scrubs the botocore chain
`mock_aws()` intercepts AWS-style endpoints only, and the `Settings` the fixtures
build carries no endpoint, so an exported `AWS_ENDPOINT_URL_S3` from a real
deployment wins and the fixtures' requests leave the process. The symptom is not
a connection error: the real gateway answers
`AccessDenied: ... Forbidden: No such key: FOOBARKEY` and most route tests fail
(67 of 132 before the fix). A `.env` in the checkout is not the trigger -
`load_dotenv()` does not overwrite already-set variables - only an exported one
is, which is what `set -a; . ./.env` produces in a shell that later runs pytest.
The autouse `isolated_aws_chain` fixture deletes those variables for every test,
so the suite is green in a polluted shell. That is safe because no test reads the
process environment for configuration: each builds an explicit `Settings`, every
`Settings.from_env` call passes a dict, and no test calls `create_app()` without
settings. Keep it that way - a test that started reading ambient configuration
would have to opt out of the fixture instead of removing it.

## Conventions
- Pins are generated by `pip-compile`, never hand-edited. Use exactly the
  commands recorded in each file's header, with the Python version that header
  names (3.14, matching the image and CI):
  `pip-compile --generate-hashes` for `requirements.txt`, and
  `pip-compile --allow-unsafe --generate-hashes requirements-dev.in` for the dev
  pins (`moto` drags `setuptools` in, and pip-tools will not pin an unsafe
  package without the flag). Dropping `--generate-hashes` breaks the hashed
  installs that both the Dockerfile (`pip install --require-hashes`) and CI
  (`pip install -r requirements.txt -r requirements-dev.txt`) rely on.
- Tests run against `moto`'s fake S3 (no network, no real bucket), so no
  Docker or S3 credentials are needed to run them.
- Navigation must never scan the whole bucket: one `ListObjectsV2`
  (Prefix + Delimiter='/') per calendar level.
- Never add the `muted` attribute to the player; audio beats autoplay.
- `app.main` exposes `app` through a module-level `__getattr__` (PEP 562), not a
  module-level `app = create_app()`. Importing the module must stay free of side
  effects so `tests/conftest.py` can import it in a fresh clone with no `.env`;
  `uvicorn app.main:app` still builds it and still exits on `ConfigError`, because
  uvicorn resolves the attribute after the import.
- `load_dotenv()` is called inside `create_app()` and searches upwards from
  `app/main.py`, not from the working directory. A `.env` next to the checkout is
  therefore used regardless of where uvicorn is started from, and a clone without
  one fails fast. Keep any test that asserts "no configuration" away from the
  checkout itself (see `tests/test_import_without_config.py`, which runs against a
  copy of `app/` in `tmp_path`).

## Empty common prefix (`S3_PREFIX=""`)
- Supported: cameras sit at the bucket root, keys are `<camera>/<YYYY>/...` with
  **no leading slash**. An S3 key starting with `/` addresses a different object.
- `join_prefix()` is for directories only (it appends a trailing `/`); build clip
  keys as `join_prefix(...) + filename`.
- The camera list always lives at the site root `/`, so `build_path(common)` is
  `/` in both modes; a camera page is `/cam/` when the prefix is empty.
- With `Prefix=''`, `ListObjectsV2` also returns a `/` CommonPrefix when a
  degenerate `/`-keyed object exists; it is filtered as out-of-layout.
- `S3_PREFIX` unset or empty (or `/`) means the bucket root, matching the
  archiver's default; there is no default folder name.

## Out-of-layout folders never link
Listing used to call `int(name)` directly, so a stray folder such as
`<prefix>/<camera>/latest/` returned HTTP 500 (pre-existing bug, surfaced by running
the empty-prefix config against real Garage). `browse._directory_entry` now
validates each folder against the level regex, refuses ambiguous four-digit
camera names, and catches `ValueError`; such entries get `url=None` and render
as `.tree__plain` text. Traversal (`parse_path`, next/previous) was already
strict and still 404s.

## Period navigation (month and day pages)
- Levels are named after the folders they list: LEVEL_DAYS is the month page,
  LEVEL_HOURS the day page. `_PERIOD_LEVELS` maps them to PERIOD_MONTH/PERIOD_DAY.
- `archive.period_navigation` reuses `find_next_hour`/`find_previous_hour` with
  anchor hours placed outside the current period: back = first day 00:00,
  forward = last day 23:00 (last day via `calendar.monthrange`, so February is
  correct). Listing pages have no hour of their own, hence the extremes.
- `browse.PeriodRef` carries camera/year/optional-day. Keeping day separate is
  what guarantees a month page links to a month page; do not pass HourRef URLs
  to those templates.
- `partials/period-nav.html` is included twice via `{% with nav_position=... %}`
  (a bare `{% include ... with x=1 %}` is invalid Jinja). Both landmarks need
  distinct aria-labels.

## Camera page (months grouped by year)
- `LEVEL_YEARS` is the camera page. `BrowseService._year_groups` turns its year
  entries into `YearGroup` records and lists each year's months with one extra
  `list_level` call per year. Never walk deeper than that.
- Entries that are not years (stray folders, files) stay in `context.entries`
  and render in the normal `.tree` nav, so grouping cannot hide data.
- `browse.html` renders `context.year_groups` first, then `context.entries`.
  The `<h2>` per year links to the year page, which still exists as its own
  listing and breadcrumb step.

## Theming and the JavaScript-free catalog
`tests/test_routes.py::test_page_needs_no_javascript_for_navigation` asserts
`"<script" not in body` for a month page, so no catalog page may carry a script -
not even a tiny inline one. The dark theme therefore lives entirely in
`styles.css` behind `@media (prefers-color-scheme: dark)` and follows the
operating system: a media query cannot flash the wrong palette the way a
`localStorage` bootstrap script does, and it keeps that test honest. Adding a
theme switch to the catalog means changing that test first, and it exists to
protect "browsing works with JS disabled", so prefer keeping it.
The palette is expressed only through the `:root` custom properties, in both
themes; anything new must use them rather than a literal color, or it will be
unreadable in one of the two. Text values clear 4.5:1 and border values 3:1
against both `--bg` and `--panel`.

## Error pages say what broke and where to go instead
`browse.explain_path(common_prefix, request_path)` reads the failing address
segment by segment and returns `(reason, Suggestion)`. The reason names the
first folder that cannot be right (`'112' is not a day of the month`), including
calendar gaps (`no day 30 in February 2026`), and the suggestion is the deepest
page the *valid* prefix describes: an impossible day offers its month, an
impossible hour its day, an address below an hour offers that hour. When every
segment is well-formed the address is simply empty, so the suggestion steps up
one level - an empty hour offers its day, never the site root.

Both `InvalidPath` and `LevelNotFound` consult it, because `parse_path` accepts
any well-formed path and only the listing discovers that February 30 has no
clips; the reason from `explain_path` is the more specific of the two messages.
`None, None` means the address renders (a route or a generic 404 is the one
showing it), which is why the root returns no reason even under a prefix.

The suggestion is a `.btn--primary` link, *not* a crumb: breadcrumbs render
their last entry with `aria-current="page"`, which would claim the target is the
page you are on. It is the page you meant, so it is a button, and the camera
list follows as the secondary button only when the target is deeper than the
root. Tests in `tests/test_error_pages.py` build every address with `build_path`
and `url_path`, following the no-date-literals convention the other test files
already keep.

## Page titles
`BrowseService._title` delegates to `_heading`, so a tab reads
`Dacha - October 2026 · Video archive` and the root reads `Cameras · Video
archive` rather than repeating the site name. Do not reintroduce a title built
from bare numbers: a tab reading `13` identifies nothing.

## The page behind the player must not scroll
`player.js` adds `has-modal` to `<html>`; `styles.css` turns off overflow and
pads by `--scrollbar-offset`, which `lockPageScroll()` measures *before* the
scrollbar disappears (hiding it is what changes `clientWidth`, so measuring
afterwards yields 0 and the layout jumps). `.modal__panel` needs
`overscroll-behavior: contain` so scrolling to the end of a tall panel does not
hand the leftover scroll back to the page.
